# HW1 (після L01–L02): логування + prompt registry

Мета тижня: запит проходить крізь систему і лишає слід, а промпт стає версіонованим
артефактом, а не рядком у коді.

## Обов'язково

1. Розбирається, як запит пише рядок у таблицю `requests` (у стартері це вже працює).
2. Переносить system-промпт із хардкоду в таблицю `prompts`: сервіс бере активну версію.
3. Пише версію промпта (`prompt_version`) у кожен лог-рядок.
4. Реалізує `GET /prompts` (список версій) і `POST /prompts/{version}/activate`
   (promote / rollback).

## Опційно (не оцінюється)

- Audit trail: окрема таблиця активацій — хто, коли, яку версію зробив активною.
- Версія промпта з міткою часу замість перезапису тіла.

## Що здає

PR, де чат працює, промпт живе в БД, консоль показує картку Prompt registry.

## Що перевіряє ментор

| Перевірка | Як | Очікується |
|---|---|---|
| Стек піднімається | `docker compose up --build` | усі контейнери Up, чат відповідає |
| Промпт у БД | `GET /prompts` | список версій, одна active |
| Версія в лозі | `SELECT model, prompt_version FROM requests ORDER BY created_at DESC LIMIT 3` | `prompt_version` заповнений |
| Rollback ловиться гейтом | активувати «поганий» промпт → evals; повернути → evals | червоні → зелені |

## Самоперевірка перед здачею

Активуй промпт без слова «support» → mock відповідає «не знаю», evals червоніють.
Поверни хороший → зелені. Відтворюється — registry зроблений правильно.
