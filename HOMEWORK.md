# HW2 (після L3–L4): routing + cost

Мета тижня: система сама обирає модель під задачу і знає, скільки коштує кожен запит.

## Що робить студент

1. Routing: обирає модель за задачею. Мінімум два маршрути: звичайні питання →
   `mock-mini`, повернення/скарги/термінове → `mock-strong` (обидві вже описані в
   `gateway/litellm-config.yaml`).
2. Cost: заводить табличку цін за 1k токенів, рахує вартість кожного запиту і пише
   в `cost_usd`.
3. Реалізує `GET /cost` → `{ today_usd, budget_usd }` — консоль покаже
   «Вартість сьогодні».

## Що здає

PR, де в таблиці `requests` різні моделі для різних питань і заповнений `cost_usd`;
плитка вартості в консолі жива.

## Що перевіряє ментор

| Перевірка | Як | Очікується |
|---|---|---|
| Routing працює | звичайне питання + «поверніть гроші терміново», потім `SELECT model, count(*) FROM requests GROUP BY model` | дві різні моделі |
| Cost рахується | `SELECT cost_usd FROM requests WHERE cost_usd IS NOT NULL LIMIT 3` | ненульові значення |
| Консоль | плитка «Вартість сьогодні» | число, не «—» |
| Evals | прогін | зелені |

## Самоперевірка перед здачею

Напиши боту звичайне питання і «поверніть гроші терміново» — у БД мають з'явитися
дві різні моделі.
