# HW3 (після L05–L06): кеш + інструменти

Мета тижня: система не палить токени на повторні питання і вміє безпечно виконувати дії.

## Обов'язково

1. Кеш відповідей: однаковий запит удруге не ходить у модель. Ключ — модель + промпт +
   повідомлення. Рахує hits / misses (знадобиться в HW5).
2. Інструменти: коли модель повертає tool_call (`lookup_order`), виконує його і додає
   результат у відповідь. Продумує timeout та ідемпотентність (повторний виклик не
   робить side-effect двічі).

## Опційно (не оцінюється)

- TTL: кешовані відповіді старіють і перезапитуються.
- Semantic cache: Redis з advanced-профілю + порівняння за схожістю, а не точним збігом.

## Що здає

PR, де другий однаковий запит відповідає миттєво (з кешу), а «Де моє замовлення #123?»
повертає відповідь з результатом інструмента.

## Що перевіряє ментор

| Перевірка | Як | Очікується |
|---|---|---|
| Кеш | два однакові запити поспіль | другий ~0ms latency |
| Інструмент | «Де моє замовлення #123?» | у відповіді результат tool-виклику |
| Ідемпотентність | той самий tool-запит повторно | без подвійного side-effect |
| Evals | прогін | зелені |

## Самоперевірка перед здачею

Два однакові запити поспіль — у другого latency ~0ms.
